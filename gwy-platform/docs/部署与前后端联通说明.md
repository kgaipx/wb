# 部署与前后端联通说明

> 配套《设计系统规范 v1.0》。本文档说明前端预览、前后端联通机制与后端部署方式。
> 最后更新：2026-08-04

## 一、已上线（前端静态预览）

- **预览地址**：https://d716d1448a70493aa69b2ba7fc78fcf0.gz4.agentos-app.net
- 内容：构建后的前端 `frontend/dist`（React + 设计系统 v1.0）。
- 说明：该预览为**纯静态托管**，后端未公网部署，因此登录/刷题/AI 讲解等需后端的操作会返回接口错误；首页、视觉与交互可完整查看。完整功能需按第四节让后端可达。

## 二、前端构建

```bash
cd frontend
npm install
npm run build          # tsc --noEmit 类型校验 + vite build → dist/
```

- 构建脚本已从 `tsc -b` 改为 `tsc --noEmit && vite build`，规避非 composite 根配置在 build 模式下的兼容问题。
- 设计系统样式来自 `src/theme/{tokens,global,components}.css`，已在 `main.tsx` 引入。

## 三、前后端联通机制（WBS 联通）

| 关注点 | 实现 | 位置 |
|---|---|---|
| 接口基址 | `BASE = import.meta.env.VITE_API_BASE \|\| "/api"`，部署时可经环境变量指向独立后端域名 | `frontend/src/api/client.ts` |
| 开发代理 | `vite` 将 `/api` 代理到 `http://localhost:8000`，本地免 CORS | `frontend/vite.config.ts` |
| 后端前缀 | 全部业务路由挂在 `/api` 下（`/api/auth`、`/api/student`、`/api/bank`、`/api/ai`、`/api/exam`、`/api/billing`、`/api/content`）；`/health` 另提供 `/api/health` 别名 | `backend/app/main.py`、`api/router.py` |
| CORS | 由 `CORS_ORIGINS` 环境变量控制（逗号分隔），需包含前端来源 | `backend/app/core/config.py` |

**本地一键联调**：

```bash
# 终端 1：后端
cd backend && uvicorn app.main:app --reload --port 8000
# 终端 2：前端（自动代理 /api → :8000）
cd frontend && npm run dev      # http://localhost:5173
```

## 四、后端部署

### 方式 A：本地 / 虚拟机直接运行

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # 填入 LLM_API_KEY / LLM_BASE_URL / LLM_MODEL 等
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

- 开发期（`APP_ENV != production`）启动自动建表并注入示范题与知识片段，零外部依赖即可联调。
- 让前端连通：构建前端时设置 `VITE_API_BASE=https://<你的后端域名>`，并在后端 `.env` 设置 `CORS_ORIGINS` 包含前端域名（预览地址或自有域名）。

### 方式 B：Docker / 容器

已提供 `backend/Dockerfile`；`docker-compose.yml` 新增 `app` 服务，可一键起「MySQL + Redis + 后端」：

```bash
docker compose up -d            # 启动 mysql / redis / app（app 依赖二者健康后启动）
# 后端地址：http://localhost:8000
```

生产镜像构建：`docker build -t gwy-backend ./backend`。
